# 旅迹｜独立管理端设计规格

> 状态：已实现 / 可交互原型  
> 版本：V0.1  
> 路径：首页 `/`；管理端 `/admin/`

## 1. 决策摘要

旅行网站拆成两个职责清晰的路径：

- `/` 是面向访客的纯浏览页面，只呈现旅行轨迹、旅程信息和相册。
- `/admin/` 是面向网站主人的相册管理工作台，首页不展示入口，也不包含任何编辑按钮或编辑弹层。

当前交付仍是前端交互原型。管理端用于验证编辑流程，不包含身份认证、真实文件上传、数据库或持久化。

## 2. 设计目标

1. 保持首页安静、沉浸，不让管理操作破坏浏览体验。
2. 让网站主人在独立空间完成旅程选择和照片编排。
3. 为未来接入登录、上传服务和数据库保留清晰边界。
4. 原型中明确表达“未保存”和“仅本次会话有效”，避免产生已上传的误解。

## 3. 路径与职责

| 路径 | 用户 | 职责 | 是否从首页可见 |
| --- | --- | --- | --- |
| `/` | 访客 | 浏览目的地、路线、故事和相册灯箱 | 是 |
| `/admin/` | 网站主人 | 选择旅程并编辑照片编排 | 否，仅通过地址直接访问 |

V0.1 不做前端路由框架。`/admin/` 使用独立 HTML 页面和独立脚本；两端共享旅程数据结构和图片资源，但不共享页面状态。

## 4. 首页调整

### 4.1 保留

- 品牌、足迹、相册、关于导航。
- 目的地悬停预览、点击确认和键盘切换。
- 路线、主图、说明和相册联动。
- 相册灯箱浏览。

### 4.2 移除

- 顶部“添加旅程”按钮。
- 首页中的添加旅程弹层及全部相关事件逻辑。
- 首页中任何指向 `/admin/` 的按钮、链接或提示。

首页的空余顶部区域用于保持版式平衡，不增加替代 CTA。

## 5. 管理端 V0.1 信息架构

1. **管理页头**：品牌、`ADMIN / ALBUM STUDIO` 标识、返回网站链接、未保存状态。
2. **旅程列表**：显示四段现有旅程、照片数量和当前选中状态。
3. **相册工具栏**：当前旅程名称、照片计数、“添加照片”按钮。
4. **照片编排区**：照片缩略图、标题输入、设为封面、删除和拖动排序把手。
5. **保存区**：显示“保存本次预览”按钮及原型数据提示。

桌面端采用左侧旅程列表、右侧照片工作区的双栏布局；移动端变为单列，旅程列表改为横向选择器。

## 6. 功能边界

### 6.1 包含

| 能力 | 原型行为 |
| --- | --- |
| 切换旅程 | 切换当前管理对象，并载入对应照片列表 |
| 添加照片 | 通过文件选择器选择本地图片，在当前会话中生成预览 |
| 修改标题 | 在照片卡片内编辑标题，输入即时保留在页面状态中 |
| 调整顺序 | 通过上移/下移控制或拖动排序调整照片顺序 |
| 设置封面 | 同一旅程只能有一张封面，设置新封面会替换旧封面 |
| 删除照片 | 需要二次确认；确认后从当前页面状态移除 |
| 保存预览 | 显示成功反馈，但不写入磁盘、服务器或首页数据 |
| 未保存提示 | 发生编辑后显示未保存状态；切换旅程前提示确认 |

### 6.2 不包含

- 登录、权限校验和管理端安全防护。
- 真实上传、图片压缩、云存储、数据库和 API。
- 新建或删除整段旅程。
- 编辑路线、国家、日期、坐标和旅行描述。
- 批量导入、批量删除、下载、图片裁切和滤镜。
- 刷新后恢复草稿，或把管理端修改同步到首页。
- 随笔及任何文章管理能力。

## 7. 状态模型

| 状态 | 含义 | 初始值 |
| --- | --- | --- |
| `activeTripId` | 当前正在编辑的旅程 | 京都 |
| `albumDraft` | 当前旅程的照片顺序、标题和封面状态 | 从演示数据复制 |
| `dirty` | 是否存在尚未保存预览的编辑 | `false` |
| `pendingFiles` | 本次会话选择的本地文件和临时预览 URL | 空 |
| `feedback` | 保存成功、删除确认或原型限制提示 | 无 |

管理端状态只存在于当前页面内存中。离开或刷新页面后，所有修改恢复到演示数据。

## 8. 核心用例

### ADM-01 进入管理端

- **参与者**：网站主人。
- **触发**：直接访问 `/admin/`。
- **主流程**：页面默认选择京都，显示旅程列表、相册照片和“所有改动仅用于本次预览”的提示。
- **结果**：用户能立即识别当前编辑对象及保存边界。
- **边界**：V0.1 不验证身份；知道地址的用户均可打开原型。

### ADM-02 切换正在编辑的旅程

- **触发**：选择另一段旅程。
- **主流程**：若当前没有修改，直接切换并载入目标相册。
- **分支**：若 `dirty=true`，弹出“放弃修改并切换 / 留在当前旅程”的确认。
- **结果**：确认放弃后切换；取消则保留当前状态。

### ADM-03 添加照片

- **触发**：点击“添加照片”并选择图片。
- **主流程**：
  1. 接受 JPG、PNG、WebP 或 AVIF。
  2. 为选择的文件生成本地临时预览。
  3. 新照片追加到列表末尾，标题默认为文件名，`dirty=true`。
- **异常**：非图片文件不加入列表，并显示可恢复的格式提示。
- **边界**：文件不会上传，刷新后临时预览消失。

### ADM-04 修改照片标题

- **触发**：编辑照片卡片中的标题输入框。
- **主流程**：输入即时写入 `albumDraft`，并将 `dirty` 标记为 `true`。
- **约束**：标题不能为空；失焦时为空则显示内联错误，并保留输入焦点的可恢复路径。

### ADM-05 调整照片顺序

- **触发**：拖动排序，或点击上移/下移按钮。
- **主流程**：照片在列表中移动，序号即时更新，`dirty=true`。
- **无障碍替代**：所有拖动能力必须同时提供可键盘操作的上移/下移按钮。
- **边界**：第一张不能继续上移，最后一张不能继续下移；禁用状态说明原因。

### ADM-06 设置封面

- **触发**：点击照片卡片的“设为封面”。
- **主流程**：新照片显示封面标识，原封面恢复普通状态，`dirty=true`。
- **约束**：每段旅程始终恰好有一张封面；删除封面时系统将下一张设为封面。

### ADM-07 删除照片

- **触发**：点击“删除”。
- **主流程**：系统显示包含照片标题的确认弹层；确认后移除照片并标记未保存。
- **恢复**：取消确认不会改变列表。
- **约束**：相册只剩一张照片时禁用删除，并说明“至少保留一张照片”。

### ADM-08 保存本次预览

- **前置条件**：标题均有效且 `dirty=true`。
- **触发**：点击“保存本次预览”。
- **主流程**：按钮立即进入短暂保存状态，随后显示“预览已保存，本地刷新后仍会恢复”的反馈，并将 `dirty=false`。
- **边界**：这是交互反馈演示，不产生持久化，也不影响首页。

### ADM-09 离开管理端

- **触发**：点击“返回网站”。
- **主流程**：若无未保存修改，直接返回 `/`；若存在修改，提示放弃或取消离开。
- **结果**：放弃后进入首页；取消后继续编辑。

## 9. 组件状态与反馈

| 组件 | 必需状态 |
| --- | --- |
| 旅程选择项 | 默认、悬停、焦点、当前选中、存在未保存修改 |
| 添加照片 | 默认、悬停、焦点、文件读取中、格式错误 |
| 标题输入 | 默认、聚焦、已修改、空值错误 |
| 排序控制 | 默认、悬停、焦点、禁用、移动完成反馈 |
| 封面控制 | 默认、当前封面、焦点、设置完成 |
| 删除控制 | 默认、悬停、焦点、禁用、等待确认 |
| 保存按钮 | 禁用、可用、保存中、预览成功、校验失败 |

所有操作必须在 100ms 内出现视觉确认。原型中的“保存”反馈约持续 1.8 秒，且文案明确没有持久化。

## 10. 数据流与隔离

```text
src/trips.js（只读演示数据）
        │
        ├── 首页 /：读取并渲染，不接受管理端修改
        │
        └── 管理端 /admin/：复制为 albumDraft
                              │
                              └── 页面内编辑与预览，刷新即丢弃
```

首页脚本不引用管理端组件；管理端脚本不操作首页 DOM。未来接入 API 时，两端只通过统一的 Trip / Photo 数据契约通信。

## 11. 视觉方向

- 延续首页的温暖纸张、宋体与等宽元数据体系，保证品牌一致性。
- 管理端更克制和工具化：降低装饰性动效，提高信息密度与操作可见性。
- 不使用齿孔或邮票轮廓作为照片管理卡片，避免装饰影响编辑效率。
- 危险操作使用文字“删除”与确认文案，不只依赖红色或垃圾桶图标。

## 12. 验收标准

- 首页不存在“添加旅程”、相册编辑或 `/admin/` 入口。
- `/admin/` 可直接打开，并默认显示京都相册。
- 可以在页面内完成添加、改标题、排序、设封面和删除的演示流程。
- 编辑后显示未保存状态；切换旅程和离开前可以放弃或取消。
- 保存反馈明确说明不持久化，且不会改变首页内容。
- 删除最后一张照片被阻止；删除封面后自动产生新封面。
- 所有核心操作均可通过键盘完成，弹层关闭后恢复触发元素焦点。
- 375px 与桌面尺寸无页面级横向溢出。
- 首页原有目的地切换、路线联动和灯箱功能不回归。
- 自动化测试、语法检查与浏览器冒烟测试通过，控制台无错误。

## 13. 后续产品化入口

V0.1 通过后，真实产品化需要另立范围，依次解决：身份认证与路由保护、后端数据模型、对象存储、图片处理队列、草稿与发布机制、冲突处理、审计和备份恢复。
