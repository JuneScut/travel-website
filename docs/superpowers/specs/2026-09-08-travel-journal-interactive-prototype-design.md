# 旅迹｜交互原型设计文档

> 文档状态：已实现 / 可交互原型  
> 当前版本：V0.1  
> 设计范围：访客首页中的旅行轨迹展示、目的地切换与相册浏览  
> 明确排除：随笔、编辑入口、真实上传、账号与线上数据服务  
> 管理端：独立放置于 `/admin/`，详见 [独立管理端设计规格](./2026-09-12-travel-journal-admin-design.md)

## 1. 产品目标

「旅迹」是一个个人旅行档案网站。当前原型用于验证两件事：

1. 用户能否通过一个有记忆点、但不过度“邮票化”的目的地索引进入不同旅程。
2. 路线、主照片、地点信息和相册能否形成连贯的旅行浏览体验。

本阶段交付物是前端交互原型，不是可运营产品。页面中的四段旅程和照片均为本地演示数据。

## 2. 用户与使用场景

### 2.1 角色

| 角色 | 说明 | 当前权限 |
| --- | --- | --- |
| 访客 | 浏览网站的人，也可能是未来的朋友、同事或公开访问者 | 浏览旅程、切换地点、查看相册 |
| 网站主人 | 旅行内容的拥有者 | 通过独立 `/admin/` 路径进入管理原型 |

首页不提供管理端入口。当前没有登录态，管理端原型通过直接访问 `/admin/` 打开。

### 2.2 核心场景

- 访客第一次进入网站，快速理解主人去过多少城市和国家。
- 访客选择一个目的地，查看旅行路线、时间和代表照片。
- 访客连续浏览一组照片，再返回原来的相册位置。
- 网站主人通过独立管理端编排相册，不干扰首页的访客体验。

## 3. 功能边界

### 3.1 本版本包含（In Scope）

| 模块 | 能力 | 数据状态 |
| --- | --- | --- |
| 首页概览 | 品牌、旅行统计、四个目的地索引 | 静态演示数据 |
| 目的地选择 | 悬停预览、点击确认、左右方向键循环切换 | 仅当前页面内存状态 |
| 旅程详情 | 联动展示路线节点、日期、坐标、主图和一句旅行描述 | 静态演示数据 |
| 相册 | 每个目的地显示 6 个照片入口 | 本地图片及不同裁切位置 |
| 灯箱 | 放大照片、上一张、下一张、键盘切换和关闭 | 仅当前页面状态 |
| 响应式 | 桌面编辑式网格；移动端单列及横向目的地索引 | 375px—桌面宽度 |
| 无障碍基础 | 语义区块、跳至正文、键盘操作、可见焦点、`aria-pressed`、原生 `dialog` | 已实现 |

### 3.2 本版本不包含（Out of Scope）

- 不包含随笔入口、文章列表、文章详情或富文本编辑器。
- 不支持真实照片选择、拖放解析、压缩、上传或云端存储。
- 首页不提供任何添加、编辑、删除或排序操作。
- 不支持修改、删除、排序或隐藏已有旅程。
- 不接入地图 SDK，不绘制真实地图、GPS 轨迹或路线导航。
- 不支持账号、登录、权限、隐私分组或仅好友可见。
- 不支持评论、点赞、分享、搜索、筛选或多语言。
- 不提供后台管理、数据库、API、统计分析或部署运维能力。

### 3.3 原型限制

- 四个目的地各使用一张本地摄影素材，通过不同 `object-position` 模拟 6 张相册照片；正式版本应替换为独立原图和缩略图。
- 首页的城市数、国家数和照片数是氛围性演示文案，不从旅程数据自动计算。
- 页面刷新后恢复默认目的地“京都”，不记录用户上次浏览位置。
- 首页与管理端不共享页面状态；管理端原型修改不会同步到首页。

## 4. 信息架构

1. 顶部导航：品牌、足迹、相册、关于。
2. 首屏：产品主张、旅行统计、目的地索引。
3. 当前旅程：路线时间轴、坐标、主照片、日期和场景说明。
4. 当前相册：与当前目的地同步的 6 张图片入口。
5. 页脚：版权、产品关键词和当前地点坐标。
6. 覆盖层：照片灯箱。

## 5. 状态模型

| 状态 | 含义 | 初始值 | 变化来源 |
| --- | --- | --- | --- |
| `selectedTrip` | 用户已经确认的旅程 | 京都 | 点击索引、方向键、上一/下一旅程 |
| `previewTrip` | 鼠标暂时指向的旅程 | 无 | 索引 `pointerenter` / `pointerleave` |
| `currentTrip` | 当前画面正在呈现的旅程 | 京都 | 确认选择或悬停预览 |
| `lightboxIndex` | 灯箱中的照片序号 | 0 | 点击缩略图、上一张/下一张、方向键 |
| `overlay` | 当前打开的覆盖层 | 无 | 打开/关闭照片灯箱 |

核心规则：悬停只改变预览内容，不改变已确认的 `selectedTrip`；指针离开后恢复已确认旅程。点击或键盘切换才会提交新的选择。

## 6. 核心用例

### UC-01 首次进入网站

- **参与者**：访客
- **前置条件**：本地静态资源可加载。
- **触发**：打开首页。
- **主流程**：
  1. 页面显示品牌、旅行统计和四个目的地索引。
  2. 系统默认选中“京都”，索引呈放大、清晰状态并标记 `aria-pressed="true"`。
  3. 京都的路线、主图、描述、相册和坐标同步出现。
- **结果**：访客无需操作即可理解网站用途并开始浏览。
- **异常/降级**：启用减少动态效果时取消主要动画，但内容和功能不变。

### UC-02 悬停预览目的地

- **参与者**：使用鼠标或触控板的访客
- **前置条件**：首页已加载，当前存在一个已确认旅程。
- **触发**：指针进入另一张目的地索引。
- **主流程**：
  1. 目标索引放大、变清晰；其他索引退后。
  2. 路线、主图、标题、日期、描述、坐标和相册即时切换。
  3. 标题上方状态文案显示 `PREVIEW`。
  4. 指针离开后恢复到上一次已确认旅程。
- **结果**：用户可以快速探索而无需提交选择。
- **边界**：悬停不会改变 `aria-pressed`，移动端不依赖悬停完成任务。

### UC-03 确认选择目的地

- **参与者**：访客
- **触发**：点击一个目的地索引。
- **主流程**：
  1. 系统将该目的地保存为当前页面内的已确认旅程。
  2. 索引获得选中视觉状态和 `aria-pressed="true"`。
  3. 页面所有旅程内容与相册同步更新。
  4. 焦点保留在所选目的地按钮上，避免页面跳动。
- **结果**：指针离开后仍保持该旅程。

### UC-04 使用键盘切换旅程

- **参与者**：键盘用户
- **前置条件**：焦点位于目的地索引，或用户使用旅程详情中的前后按钮。
- **触发**：按 `←` / `→`，或点击“上一段旅程 / 下一段旅程”。
- **主流程**：
  1. 系统按照里斯本 → 京都 → 冰岛 → 巴黎的顺序切换。
  2. 到达首尾时循环到另一端。
  3. 新旅程被确认，内容区域和相册同步更新。
  4. 焦点移动到新选中的索引。
- **结果**：用户可以不依赖鼠标完整浏览四段旅程。

### UC-05 浏览当前旅程路线

- **参与者**：访客
- **前置条件**：已存在当前旅程。
- **主流程**：
  1. 路线按时间顺序展示 4 个地点节点及日期。
  2. 第一个节点以强调色标记为起点。
  3. 主图、国家、旅程日期、坐标和一句描述与当前旅程一致。
- **结果**：访客能快速建立地点、时间和影像之间的关系。
- **边界**：节点不可点击，不提供地图定位或路线详情。

### UC-06 打开并浏览相册灯箱

- **参与者**：访客
- **触发**：点击任意相册缩略图。
- **主流程**：
  1. 系统打开模态灯箱，显示大图、标题和当前位置，如 `02 / 06`。
  2. 用户点击左右按钮或按 `←` / `→` 循环浏览。
  3. 切换时图片使用约 240ms 的轻量淡入反馈。
- **退出方式**：点击关闭按钮、点击遮罩或按 `Escape`。
- **结果**：灯箱关闭后，焦点回到打开灯箱的缩略图。
- **边界**：不支持缩放、下载、分享、收藏或手势拖拽。

### UC-07 在移动端浏览

- **参与者**：手机访客
- **前置条件**：视口宽度不高于 620px。
- **主流程**：
  1. 主导航隐藏，仅保留品牌。
  2. 目的地索引在容器内横向滚动，不造成页面级横向溢出。
  3. 路线、主图、旅程说明改为单列阅读。
  4. 相册改为两列。
- **结果**：所有核心浏览与灯箱功能可通过触控完成。

## 7. 组件状态与反馈

| 组件 | Default | Hover / Preview | Focus | Selected | Disabled / Error |
| --- | --- | --- | --- | --- | --- |
| 目的地索引 | 降低饱和度、轻微虚化 | 放大、清晰、联动预览 | 陶土色轮廓 | 放大并保持清晰 | 当前无禁用与错误态 |
| 相册缩略图 | 图片与标题 | 图片轻微放大 | 清晰焦点轮廓 | 不保持选中 | 图片加载失败态尚未设计 |
| 前后切换按钮 | 细线框 | 深色反转 | 浏览器可见焦点 | 按压反馈 | 循环浏览，无禁用态 |
| 灯箱 | 关闭 | 不适用 | 打开后焦点进入灯箱 | 模态打开 | 可通过按钮、遮罩或 Escape 退出 |

## 8. 视觉与动效原则

- **基调**：温暖石灰白、墨黑、目的地动态强调色。
- **字体**：中文宋体风格显示字体 + 紧凑等宽元数据字体。
- **布局**：大留白、细分隔线、非对称编辑网格。
- **影像**：低饱和旅行纪实感，避免常规旅游宣传图。
- **邮票元素边界**：仅在目的地图片索引使用轻微齿孔轮廓；不使用邮戳、邮资数值、信封、邮筒或大面积邮政符号。
- **动效**：索引状态约 260—420ms；图片切换约 240—420ms；动效只表达焦点和内容切换。
- **减少动态效果**：遵循 `prefers-reduced-motion`，将动画降至近乎即时。

## 9. 无障碍与响应式要求

- 所有主要按钮保持至少约 44×44px 的操作区域。
- 目的地索引必须是可聚焦按钮，并使用 `aria-pressed` 表达确认状态。
- 所有无文本图标按钮必须有可读的 `aria-label`。
- 灯箱使用原生 `dialog`，关闭后恢复触发元素焦点。
- `Escape` 可以退出灯箱；灯箱支持键盘前后浏览。
- 页面提供“跳到主要内容”链接。
- 375px 下不得出现页面级横向滚动；1024px 以上显示完整编辑式网格。

## 10. 数据结构

每段旅程至少包含：

```text
Trip
├── id / city / latin / country
├── date / shortDate / dateRange
├── coords / title / description
├── accent / shader / hero
├── route[place, date]
└── gallery[src, alt, caption, position]
```

当前数据来自 `src/trips.js`，不通过 API 获取。

## 12. 下一阶段候选能力（不属于当前承诺）

如果从原型进入可用产品，建议按以下顺序推进：

1. 独立照片资源、缩略图生成与图片加载失败状态。
2. 将独立 `/admin/` 原型接入真实上传、校验、草稿、失败重试和保存反馈。
3. 旅程管理：新增、编辑、删除、排序、封面设置与可见性。
4. 地图与真实 GPS 轨迹。
5. 账号和隐私权限。

随笔模块继续保持独立，不进入上述默认范围，需单独确认后再设计。
